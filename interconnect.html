심화 · CPU · GPU · NIC 데이터 이동

"CPU와 GPU는 정보를 어떻게 주고받나? 메모리는 공유하나? NIC은 어떻게 연결되나?" — vRAN 성능을 좌우하는 가장 중요한 주제입니다. 신호처리 커널이 아무리 빨라도, 데이터 이동이 느리면 실시간 마감을 못 맞춥니다.

1. 시스템 큰 그림

일반적인 GPU 서버(외장/discrete GPU)는 이렇게 생겼습니다. CPU와 GPU는 물리적으로 분리된 칩이고, 각자 자기 메모리를 가지며, PCIe라는 버스로 연결됩니다. NIC(네트워크 카드)도 같은 PCIe에 붙습니다. 

          ┌─────────────── 메인보드 ───────────────┐
          │                                          │
  ┌───────┴───────┐                       ┌──────────┴──────────┐
  │   CPU         │                       │   GPU               │
  │  + 시스템 RAM  │◀───── PCIe 버스 ─────▶│  + VRAM (전용 메모리) │
  │  (DDR, 수십GB) │                       │  (HBM/GDDR, 빠름)    │
  └───────┬───────┘                       └─────────────────────┘
          │                                          ▲
          │  PCIe                                     │ (GPUDirect 시 직접)
          ▼                                          │
  ┌───────────────┐                                  │
  │   NIC         │──────────────────────────────────┘
  │ (네트워크 카드) │      외부에서 들어오는 데이터(예: 안테나 IQ)
  └───────────────┘

여기서 핵심 질문 3개를 차례로 풉니다: ① CPU·GPU가 메모리를 공유하나? ② PCIe·NVLink가 뭔가? ③ NIC 데이터가 GPU로 어떻게 들어가나?

2. CPU와 GPU는 메모리를 공유하는가?

경우에 따라 다릅니다. 3가지 모델을 구분하는 게 중요합니다.

① 분리형 (Discrete GPU) — 공유 안 함 가장 일반적

데스크탑/서버의 외장 GPU(A100, H100, RTX 등). CPU는 시스템 RAM, GPU는 VRAM을 따로 갖습니다. 데이터를 쓰려면 PCIe로 명시적 복사가 필요합니다. Part 2의 cudaMemcpy가 바로 이 복사입니다. 

// CPU RAM(hA) → GPU VRAM(dA) 로 물리적 복사가 일어남
cudaMemcpy(dA, hA, bytes, cudaMemcpyHostToDevice);

② Unified Memory — "가상으로" 공유

cudaMallocManaged로 할당하면 CPU·GPU가 같은 포인터를 쓸 수 있습니다. 단, 물리적으로 합쳐진 건 아니고 — 시스템이 필요할 때 페이지를 자동으로 복사·이동(migration)해 줍니다. 편하지만, 뒤에서 여전히 PCIe 전송이 일어나므로 성능 튜닝은 따로 필요합니다.

③ 물리적 공유 (Coherent) — 진짜 공유 vRAN 트렌드

NVIDIA Grace Hopper(GH200) 같은 통합 구조에서는 CPU(Grace)와 GPU(Hopper)가 NVLink-C2C로 연결되어 물리적으로 메모리를 일관성(coherence) 있게 공유합니다. 복사 없이 양쪽이 같은 데이터를 직접 접근 → 지연이 크게 줄어듭니다. (참고: 노트북의 통합 GPU나 일부 SoC도 메모리를 공유하지만, 이건 저성능 쪽 이야기입니다.)

모델메모리데이터 전달예시
분리형RAM / VRAM 분리PCIe로 명시적 복사A100, H100(PCIe)
Unified Memory분리(가상 통합)자동 페이지 이동위 GPU + 소프트웨어
물리적 공유일관성 공유복사 없이 직접 접근Grace Hopper GH200
📡 vRAN 관점

vRAN은 데이터를 끊임없이 흘려보내므로 PCIe 복사 한 번 한 번이 지연 예산을 갉아먹습니다. 그래서 NVIDIA가 vRAN 플랫폼을 Grace Hopper(메모리 공유) 방향으로 미는 것입니다 — CPU↔GPU 복사 자체를 없애려는 거죠.

3. PCIe vs NVLink — 연결 통로

  • PCIe — 모든 부품(GPU, NIC, SSD)을 잇는 범용 버스. 세대마다 대역폭이 오릅니다(예: PCIe Gen5 x16 ≈ 양방향 128GB/s급). 범용이지만 GPU끼리 통신엔 상대적으로 느립니다.
  • NVLink — NVIDIA의 GPU 전용 고속 링크. PCIe보다 훨씬 높은 대역폭으로 GPU↔GPU(또는 Grace의 C2C로 CPU↔GPU)를 연결. 여러 GPU로 부하를 나누는 멀티-GPU vRAN에서 중요합니다.
💡 왜 대역폭이 중요한가

GPU 연산은 빠른데 데이터가 그 속도로 도착하지 못하면 GPU가 놀게 됩니다(memory-bound의 시스템 버전). "연산 능력"만큼 "데이터를 얼마나 빨리 넣고 빼느냐(I/O 대역폭)"가 vRAN 설계의 핵심 지표입니다.

4. 실제 전송은 어떻게? — DMA와 Pinned Memory

CPU가 데이터를 한 바이트씩 GPU에 떠먹이는 게 아닙니다. DMA(Direct Memory Access) 엔진이 CPU를 대신해 메모리 블록을 옮깁니다. CPU는 "옮겨라"라고 지시만 하고 다른 일을 합니다.

  • Pageable memory(일반 malloc) — OS가 페이지를 옮길 수 있어, DMA 전에 임시 버퍼 복사가 추가로 생겨 느림.
  • Pinned (page-locked) memory(cudaMallocHost) — 물리 주소가 고정되어 DMA가 바로 가능 → 더 빠르고 비동기 전송 가능. 스트림 overlap의 전제 조건입니다.
float* hA;
cudaMallocHost(&hA, bytes);   // pinned memory → 빠른 DMA + 비동기 복사 가능
cudaMemcpyAsync(dA, hA, bytes, cudaMemcpyHostToDevice, stream);

5. nvidia-smi 와 토폴로지 보기

nvidia-smi (NVIDIA System Management Interface)는 GPU 상태를 보는 기본 도구입니다. 사용률, 메모리, 온도, 전력, 돌고 있는 프로세스를 보여줍니다. 

# GPU 현재 상태 (사용률·메모리·온도·프로세스)
nvidia-smi

# 1초마다 갱신해서 모니터링
nvidia-smi -l 1

그리고 궁금해하신 "연결 그래프" — 어떤 GPU·NIC가 어떻게 이어져 있는지는 이 명령으로 봅니다: 

# CPU·GPU·NIC 간 연결 토폴로지를 행렬로 출력
nvidia-smi topo -m

출력의 기호가 연결 종류를 뜻합니다:

기호의미
NV#NVLink로 직접 연결 (가장 빠름, #는 링크 수)
PIX / PXB같은 PCIe 스위치를 통한 연결 (빠름)
NODE / SYS같은/다른 CPU(NUMA 노드)를 거치는 연결 (느림)
X자기 자신
💡 왜 보냐면

GPU와 NIC가 같은 PCIe 스위치/같은 CPU 소켓(NUMA 노드)에 붙어 있어야 GPUDirect가 빠릅니다. 멀리 떨어져 있으면(SYS) CPU 간 링크를 거쳐 지연이 늘죠. vRAN 서버를 셋업할 때 이 토폴로지를 보고 NIC과 GPU를 같은 노드에 배치합니다.

6. NIC과 GPU — GPUDirect RDMA

이제 핵심입니다. 안테나에서 들어온 무선 데이터는 NIC(네트워크 카드)를 통해 서버로 들어옵니다. 이 데이터가 GPU까지 가는 경로가 두 가지입니다.

일반 경로 (느림) — CPU를 거침

NIC ──▶ CPU 시스템 RAM ──▶ (cudaMemcpy) ──▶ GPU VRAM
        ↑ CPU가 개입, 메모리 2번 거침 → 지연·지터 증가

GPUDirect RDMA (빠름) — CPU 우회 vRAN 핵심

NIC ──────────(PCIe 직접 DMA)──────────▶ GPU VRAM
     CPU·시스템 RAM을 건너뜀 → 지연 최소, CPU 부하 0

GPUDirect RDMA는 NIC이 시스템 RAM을 거치지 않고 GPU 메모리에 직접 DMA로 데이터를 쓰는 기술입니다. CPU가 데이터 경로에서 완전히 빠지므로 지연과 지터가 크게 줄어듭니다 — μs 단위 마감이 걸린 vRAN에 결정적입니다.

🔧 관련 기술 묶음
  • GPUDirect RDMA — NIC ↔ GPU 직접 전송.
  • DPDK — 커널 네트워크 스택을 우회해 유저공간에서 초저지연 패킷 처리. O-RAN Fronthaul 패킷 수신에 사용.
  • DOCA / BlueField DPU — NIC에 프로세서를 얹은 DPU가 패킷 처리·시각 동기(PTP)를 전담해 CPU·GPU를 신호처리에 집중시킴.
  • PTP (정밀 시각 동기) — Fronthaul은 ns~μs 수준 시각 동기가 필수. NIC/DPU가 담당.

전체 그림: vRAN 데이터 흐름

  [안테나/RU]
      │ Fronthaul (eCPRI 패킷, O-RAN 7.2x)
      ▼
  ┌─────────┐   GPUDirect RDMA
  │  NIC/DPU │═══════════════════╗   (CPU·RAM 우회)
  └─────────┘                    ║
                                 ▼
                          ┌────────────┐
       제어·스케줄 ◀──────│  GPU (cuPHY) │  L1 신호처리
       ┌─────────┐        │   VRAM      │  (FFT·채널추정·
       │  CPU    │◀──────▶│             │   MIMO·LDPC)
       │ (Grace) │ NVLink │            │
       └─────────┘  -C2C  └────────────┘

정리하면 — NIC/DPU가 안테나 데이터를 GPUDirect로 GPU에 직접 넣고, GPU가 L1 신호처리를 인라인으로 끝내며, CPU(Grace)는 NVLink로 메모리를 공유하며 제어·스케줄링만 맡습니다. 데이터 복사를 최대한 없애는 게 전체 설계 철학입니다.

✅ 이 페이지 정리

① 보통의 외장 GPU는 메모리를 공유하지 않고 PCIe로 복사한다. Grace Hopper는 NVLink로 물리적 공유. ② 전송은 DMA가 하고, pinned memory가 빠르다. ③ nvidia-smi topo -m으로 GPU·NIC 연결을 본다. ④ NIC→GPU는 GPUDirect RDMA로 CPU를 건너뛰는 게 vRAN의 핵심. "복사를 없애라"가 전체 키워드입니다.
