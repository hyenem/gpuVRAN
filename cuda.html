Part 2 · CUDA 프로그래밍

Part 1의 하드웨어 개념을 실제 코드로 다룹니다. CUDA는 C++ 확장이며, "어떤 데이터를 어떤 스레드가 처리할지" 매핑하는 것이 핵심입니다.

2.1 프로그래밍 모델 — Grid / Block / Thread

CUDA에서 병렬 작업은 3단 계층으로 조직됩니다. 이 구조가 Part 1의 하드웨어(SM, warp)에 그대로 매핑됩니다.

  • Thread — 가장 작은 실행 단위. 하나의 데이터 원소를 처리.
  • Block (thread block) — 스레드의 묶음. 같은 블록 안의 스레드는 shared memory를 공유하고 동기화(__syncthreads())할 수 있음. 하나의 SM에서 실행됨.
  • Grid — 블록의 묶음. 커널 하나를 실행하면 grid 전체가 GPU에 펼쳐짐.
// 각 스레드는 자신의 전역 인덱스를 이렇게 계산한다
int idx = blockIdx.x * blockDim.x + threadIdx.x;
//        ↑ 몇 번째 블록    ↑ 블록 크기   ↑ 블록 내 위치
🧩 핵심 사고법

CUDA 프로그래밍 = "내가 처리할 데이터 배열의 인덱스를, 내 스레드 좌표(blockIdx, threadIdx)로부터 어떻게 계산할까?"를 정하는 일입니다. 나머지는 평범한 C++ 코드예요.

2.2 첫 커널 — 벡터 덧셈

가장 기본적인 예제, 두 벡터를 더하는 C = A + B입니다. CPU와 GPU 코드를 비교해 보세요. 

// ===== CPU 버전: 루프로 하나씩 =====
void vecAdd_cpu(float* A, float* B, float* C, int n) {
    for (int i = 0; i < n; i++)
        C[i] = A[i] + B[i];
}

// ===== GPU 버전: 각 스레드가 원소 하나 담당 =====
__global__ void vecAdd(float* A, float* B, float* C, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n)                 // 배열 범위 넘는 스레드 보호
        C[i] = A[i] + B[i];
}

__global__은 "GPU에서 실행되고 CPU에서 호출되는 함수(=커널)"라는 표시입니다. 루프가 사라진 게 핵심 — 루프 대신 수천 개의 스레드가 각자 한 원소씩 동시에 처리합니다.

호스트(CPU) 쪽 실행 코드

int n = 1<<20;                 // 약 100만 개
size_t bytes = n * sizeof(float);

float *dA, *dB, *dC;            // GPU(device) 메모리 포인터
cudaMalloc(&dA, bytes);
cudaMalloc(&dB, bytes);
cudaMalloc(&dC, bytes);

cudaMemcpy(dA, hA, bytes, cudaMemcpyHostToDevice);  // CPU→GPU 복사
cudaMemcpy(dB, hB, bytes, cudaMemcpyHostToDevice);

int threads = 256;                              // 블록당 스레드 (보통 128~512)
int blocks  = (n + threads - 1) / threads;   // 올림 나눗셈
vecAdd<<<blocks, threads>>>(dA, dB, dC, n);    // ← 커널 실행!

cudaMemcpy(hC, dC, bytes, cudaMemcpyDeviceToHost);  // GPU→CPU 결과 회수
cudaFree(dA); cudaFree(dB); cudaFree(dC);

<<<blocks, threads>>>가 CUDA 특유의 실행 구성(launch configuration) 문법입니다. "블록 몇 개, 블록당 스레드 몇 개로 grid를 펼쳐라"는 뜻이죠.

⚠️ 비동기 주의

커널 실행(<<<>>>)은 비동기입니다 — CPU는 GPU 완료를 기다리지 않고 다음 줄로 갑니다. 결과가 필요하면 cudaMemcpy(자동 동기화) 또는 cudaDeviceSynchronize()로 기다려야 합니다. 이 비동기성이 나중에 성능의 무기가 됩니다(스트림).

2.3 메모리 관리

전통적 방식은 위처럼 cudaMalloc + cudaMemcpy로 명시적 복사를 합니다. 더 편한 방법도 있습니다.

Unified Memory (통합 메모리)

float *A;
cudaMallocManaged(&A, bytes);   // CPU/GPU가 같은 포인터로 접근
// 명시적 cudaMemcpy 없이 CPU에서 쓰고 GPU에서 읽기 가능
// → 시스템이 필요할 때 자동으로 페이지 이동 (편하지만 성능 튜닝은 별도)
💡 Pinned Memory

일반(pageable) 호스트 메모리 대신 cudaMallocHost로 할당한 pinned memory를 쓰면 CPU↔GPU 전송이 빨라지고 비동기 복사가 가능해집니다. vRAN처럼 데이터를 계속 흘려보내는(streaming) 워크로드에서 중요합니다.

에러 체크는 습관처럼

#define CUDA_CHECK(call) do { \
    cudaError_t e = (call); \
    if (e != cudaSuccess) { \
        fprintf(stderr, "CUDA error %s:%d: %s\n", \
            __FILE__, __LINE__, cudaGetErrorString(e)); \
        exit(1); \
    } \
} while(0)

CUDA_CHECK(cudaMalloc(&dA, bytes));   // 모든 CUDA 호출을 감싸기

2.4 스트림 · 비동기 — 처리량의 핵심

CUDA 스트림은 GPU 작업의 "작업 큐"입니다. 같은 스트림 안의 작업은 순서대로, 다른 스트림끼리는 병렬로 실행됩니다. 이를 이용해 "데이터 전송"과 "연산"을 겹쳐(overlap) 숨길 수 있습니다. 

cudaStream_t s1, s2;
cudaStreamCreate(&s1);
cudaStreamCreate(&s2);

// 청크 0은 s1에서, 청크 1은 s2에서 — 전송과 연산이 겹쳐 돌아감
cudaMemcpyAsync(dA0, hA0, sz, cudaMemcpyHostToDevice, s1);
kernel<<<b, t, 0, s1>>>(dA0);

cudaMemcpyAsync(dA1, hA1, sz, cudaMemcpyHostToDevice, s2);
kernel<<<b, t, 0, s2>>>(dA1);
📡 vRAN과의 연결

vRAN은 무선 신호가 끊임없이 들어오는 파이프라인입니다. 스트림으로 "안테나 데이터 수신 → 신호처리 → 결과 송출"을 겹쳐 돌려 지연을 최소화하는 것이 핵심 기술입니다. Part 3의 실시간 제약과 직결됩니다.

CUDA Graphs

매번 같은 커널·복사 순서를 반복한다면, 이를 하나의 그래프로 캡처해 launch 오버헤드를 줄일 수 있습니다. μs 단위 지연이 중요한 vRAN L1 파이프라인에서 실제로 쓰이는 기법입니다.

2.5 성능 최적화 체크리스트

Part 1의 하드웨어 지식이 여기서 실전이 됩니다. 우선순위 순으로:

  1. 메모리 병합(coalescing) — 스레드 i가 배열 i를 읽게. 가장 효과 큼.
  2. Shared memory 재사용 — 반복 접근 데이터를 올려두고 재사용(타일링).
  3. Occupancy 확보 — 블록 크기·레지스터 사용량 조절로 SM에 충분한 warp 올리기.
  4. 분기 최소화 — warp 내 divergence 줄이기.
  5. 전송 숨기기 — 스트림으로 복사·연산 overlap, pinned memory 사용.
  6. 라이브러리 활용 — 직접 짜기 전에 cuBLAS, cuFFT, CUTLASS를 먼저 고려.

shared memory 타일링 맛보기 (행렬 곱)

__global__ void matmul(float* A, float* B, float* C, int N) {
    __shared__ float tileA[16][16];   // 블록 안에서 공유
    __shared__ float tileB[16][16];
    int row = blockIdx.y*16 + threadIdx.y;
    int col = blockIdx.x*16 + threadIdx.x;
    float sum = 0;
    for (int t = 0; t < N/16; t++) {
        tileA[threadIdx.y][threadIdx.x] = A[row*N + t*16+threadIdx.x];
        tileB[threadIdx.y][threadIdx.x] = B[(t*16+threadIdx.y)*N + col];
        __syncthreads();             // 타일 로딩 완료 대기
        for (int k = 0; k < 16; k++)
            sum += tileA[threadIdx.y][k] * tileB[k][threadIdx.x];
        __syncthreads();             // 다음 타일 덮어쓰기 전 대기
    }
    C[row*N + col] = sum;
}

각 원소를 global memory에서 매번 읽는 대신, 16×16 타일을 shared memory에 한 번 올려 재사용합니다. 메모리 접근이 수십 배 줄어 성능이 크게 오릅니다.

✅ Part 2 정리

① 커널은 __global__, 인덱스는 blockIdx*blockDim+threadIdx. ② cudaMalloc/Memcpy로 메모리 관리, 커널은 비동기. ③ 스트림으로 전송·연산 overlap. ④ 최적화는 coalescing > shared memory > occupancy 순. 이제 이걸 vRAN에 적용할 차례입니다.
