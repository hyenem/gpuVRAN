GPU 패킷 I/O: gpudev vs GPUNetIO

패킷을 GPU 메모리로 직접 다루는 두 기술입니다. 둘 다 GPUDirect 위에 서지만 — CPU가 주도하느냐 GPU가 주도하느냐가 갈립니다.

1. 핵심 차이 — 누가 주도하나

🔑 한 줄

DPDK gpudev = CPU 주도 (CPU가 Rx 루프 돌리고 데이터만 GPU 메모리에) · DOCA GPUNetIO = GPU 주도 (CUDA 커널이 직접 송수신 = GDAKIN, CPU가 데이터 경로에서 빠짐)

gpudev   :  NIC → GPU 메모리        CPU(PMD)가 "여기 패킷 왔다" 알려줌 → GPU 처리
GPUNetIO :  NIC → GPU 메모리        GPU 커널이 직접 "패킷 집어옴"(receive) → 처리 → 직접 송신

2. DPDK gpudev (rte_gpudev)

DPDK에 GPU를 끌어들이는 라이브러리(DPDK 21.11~). GPU 메모리 관리 + CPU↔GPU 조율을 추상화합니다. 단, DPDK는 본질적으로 CPU 프레임워크라 패킷 수신(poll-mode driver)은 여전히 CPU가 돌립니다.

분류함수역할
GPU 메모리rte_gpu_mem_alloc / _freeGPU 메모리 할당
호스트 메모리 등록rte_gpu_mem_registerCPU 메모리를 GPU가 보게 핀(pin)
GPU↔CPU 매핑rte_gpu_mem_cpu_mapGPU 메모리를 CPU에 노출
통신 리스트rte_gpu_comm_*CPU↔GPU 조율 (mbuf 주소 + 처리 상태 플래그)

동작 흐름

NIC → (GPUDirect) GPU 메모리에 패킷 적재
CPU(PMD):  수신한 mbuf 주소들을 "comm list"에 채움 + 플래그 set
GPU 커널:  comm list를 폴링 → 패킷 처리 → 완료 플래그 set
CPU:       완료 플래그 보고 mbuf 정리(free)
💡 comm list = 공유 메모리 핸드셰이크

CPU와 CUDA 커널이 공유하는 메모리 구조로, 각 항목이 받은 패킷(mbuf) 주소 + 처리 상태 플래그를 담습니다. "여기 패킷 왔다 / 처리 끝났다"를 주고받죠. 당신이 물어본 mbuf free 문제의 표준 메커니즘이 바로 이것 — 완료 플래그로 free 시점을 잡습니다.

한계: CPU가 매 배치 Rx해서 GPU에 "넘겨주는" 구조라, CPU가 제어 경로에 남아 있습니다.

3. DOCA GPUNetIO

NVIDIA DOCA SDK의 라이브러리. gpudev의 한계(CPU 주도)를 넘어 GPU가 네트워크 통신을 직접 제어하게 합니다. 즉 CUDA 커널 안에서 패킷을 받고 보냅니다.

핵심 기술 — GDAKIN

GDAKIN = GPUDirect Async Kernel-Initiated Network. CUDA 커널이 직접 receive/send를 트리거 → CPU가 데이터 경로에서 완전히 빠집니다. DPDK로는 이게 안 되는 이유: 제어 경로 전체를 GPU로 옮겨야 하는데 DPDK는 CPU 프레임워크라서. 그래서 NVIDIA가 별도 라이브러리를 만든 것입니다.

구성 요소

  • GPUDirect RDMA — 데이터 경로 가속 (NIC↔GPU 직접)
  • GDAKIN — 커널 주도 송수신
  • 스마트 GPU 메모리 관리
  • 세마포어 — CPU↔GPU / GPU↔GPU 저지연 메시지 패싱 (gpudev comm list와 유사 역할)
  • DOCA Flow — flow steering으로 특정 eAxC 흐름을 GPU 큐로

API(doca_gpu_dev_eth_rxq_receive_*, doca_gpu_dev_eth_txq_send_*, 세마포어 연산 등)가 CUDA device 코드(커널)에서 호출됩니다.

🔧 요구 하드웨어

ConnectX-6 Dx/7 또는 BlueField-2/3 + GPU + GPUDirect.

4. 비교 · 선택

DPDK gpudevDOCA GPUNetIO
주도권CPU (PMD가 Rx)GPU (커널이 Rx/Tx)
CPU 위치데이터/제어 경로에 남음데이터 경로에서 빠짐 (GDAKIN)
조율comm list세마포어
프레임워크DPDK (CPU 중심)DOCA (GPU 중심)
지연·CPU부하낮음더 낮음
성숙도/위치먼저 나온 단계NVIDIA 발전형 (vRAN·분석)

어느 걸 언제

  • gpudev — DPDK 기반 파이프라인이 이미 있고 "데이터를 GPU 메모리로 보내고 CPU가 조율"이면 충분할 때. 진입 장벽 낮음.
  • GPUNetIO — 최저 지연·CPU 최소 개입이 필요한 inline vRAN, NVIDIA Aerial 류. GPU가 패킷 I/O까지 쥐는 가장 GPU-중심적 구조. 타이밍·CPU 우회·결정론에 더 맞음.
✅ 한 줄 정리

gpudev는 "CPU가 GPU에게 패킷을 가져다주는" 모델, GPUNetIO는 "GPU가 직접 패킷을 집어오는" 모델입니다. 후자가 vRAN의 지향점이고, inline 가속 철학과 정확히 맞물립니다.
