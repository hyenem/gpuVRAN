⑤ CUDA Graphs

한 줄 요약 — 반복되는 GPU 작업 시퀀스를 "그래프"로 한 번 캡처해, 매번 통째로 launch해서 launch 오버헤드와 지터를 없애는 기술입니다.

5.1 왜 그래프인가 — launch 오버헤드

커널을 하나 launch할 때마다 CPU 쪽 오버헤드(드라이버 처리, ~µs)가 듭니다. 작은 커널 수십 개를 반복하면 이 비용이 쌓여 — 연산보다 launch가 병목이 되고, 커널 사이 간격과 지터가 생깁니다. 

// 매번 N번 launch → N번의 CPU 오버헤드 + 지터
a<<<...>>>(); b<<<...>>>(); c<<<...>>>(); d<<<...>>>();

// 그래프: 한 번 캡처, 매번 한 방에
cudaGraphLaunch(graphExec, stream);   // 1번 launch로 전체 시퀀스
💡 얻는 것 3가지
  • launch 비용 분할상환 — N번 → 1번
  • CPU 해방·지터↓ — CPU는 한 번 던지고, GPU가 자율 실행
  • 드라이버 최적화 — 전체 워크플로를 미리 알기에 커널 간 간격을 더 잘 짬

5.2 3단계 동작 — 정의 → 인스턴스화 → 실행

비싼 셋업은 한 번만, 실행은 싸게 반복이 핵심입니다.

단계무엇비용
① 정의노드(작업)+의존성(DAG) 구성 → cudaGraph_t1회
② 인스턴스화실행 객체로 컴파일(검증·최적화) → cudaGraphExec_t1회 (비쌈)
③ 실행cudaGraphLaunch로 반복 재생매번 (쌈)

그래프 = 노드 + 엣지의 DAG. 노드 종류: 커널, memcpy, memset, host 함수, child graph, event, conditional 등.

5.3 만드는 법 — Stream Capture vs Explicit API

① Stream Capture (가장 쉬움)

cudaStreamBeginCapture(stream, cudaStreamCaptureModeGlobal);
a<<<...,stream>>>();          // 이 블록의 작업들이 실행되지 않고
b<<<...,stream>>>();          // 그래프에 "기록"됨 (의존성은 스트림에서 추론)
cudaStreamEndCapture(stream, &graph);

② Explicit API (정밀 제어)

cudaGraphCreate(&graph, 0);
cudaGraphAddKernelNode(&nA, graph, NULL, 0, &pA);
cudaGraphAddKernelNode(&nB, graph, &nA, 1, &pB);  // nA에 의존

5.4 업데이트 — 구조는 그대로, 파라미터만

데이터 포인터·크기만 바뀌고 구조(위상)는 같다면, 재빌드 없이 파라미터만 갱신합니다.

빌드 + 인스턴스화 (1회)
 └─ 반복: cudaGraphExecKernelNodeSetParams(...) → cudaGraphLaunch(...)
  • 노드 단위 — cudaGraphExecKernelNodeSetParams 등으로 특정 노드만
  • 전체 그래프 — cudaGraphExecUpdate (위상 동일한 새 그래프로 일괄)
📌 성질

업데이트는 다음 launch부터 적용되고 진행 중 launch엔 영향 없음. 단 위상은 동일해야 함 — 노드 추가/삭제는 재빌드 필요.

5.5 고급 — Conditional Node & Device Graph Launch

Conditional Nodes (CUDA 12.3+)

그래프 구조 고정이라 동적 제어 흐름이 약점이었는데, conditional node(IF/WHILE 컨테이너)가 풉니다. body graph가 조건 변수에 따라 실행됩니다.

  • 커널에서 cudaGraphSetConditional로 조건 값 설정
  • IF: 조건≠0이면 body 1회 / WHILE: 참인 동안 반복 (가변 반복 알고리즘에 유용)

Device Graph Launch (CUDA 12+)

GPU 커널이 직접 다른 그래프를 launch — CPU를 안 거치고요. GPU 코드가 다음에 어떤 그래프를 돌릴지 동적으로 정해, CPU↔GPU 왕복을 없애는 계층적 실행이 가능합니다.

⚠️ 함정
  • 빌드·인스턴스화 비용 — 한 번만 하라. 매 반복 재빌드하면 손해.
  • 구조 고정 — 위상 변경은 재빌드. 동적 분기는 conditional node로 일부만.
  • 캡처 중 일부 동기 API 금지 — capture 모드 제약 주의.
✅ ⑤ 정리

CUDA Graphs = 정의→인스턴스화(1회)→실행(반복). 반복 커널 시퀀스를 한 번 캡처해 파라미터만 갱신하며 통째로 launch → launch 오버헤드·지터 제거. conditional node(동적 흐름)·device launch(CPU 우회)로 확장.
