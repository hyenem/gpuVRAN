⑥ 성능 최적화

①~④의 지식이 여기서 실전이 됩니다. 대부분의 GPU 커널은 메모리에서 막히므로, 메모리 접근 패턴 최적화가 가장 효과가 큽니다. 우선순위 순으로 정리합니다.

6.1 메모리 병합 (Coalescing) — 가장 효과 큼

한 warp의 32개 스레드가 연속된 메모리 주소를 읽으면, GPU는 이를 하나의 큰 트랜잭션으로 묶어 처리합니다(coalescing). 흩어진 주소를 읽으면 트랜잭션이 쪼개져 대역폭이 낭비됩니다. 

// 좋음: 스레드 i가 배열 i를 읽음 → 연속 → 병합
C[i] = A[i] + B[i];        // i = blockIdx.x*blockDim.x + threadIdx.x

// 나쁨: 스레드가 stride로 흩어진 주소 접근 → 트랜잭션 쪼개짐
C[i*stride] = A[i*stride];

황금률: "스레드 i가 배열 i를 읽게 하라." 2D 데이터는 row-major 순서로 인접 스레드가 인접 열을 읽게 인덱싱하세요.

6.2 Shared Memory 타일링 — 재사용

global memory는 느리므로, 여러 번 쓰일 데이터는 한 번 읽어 shared memory에 올려두고 재사용합니다. 행렬 곱이 대표 예입니다. 

__global__ void matmul(float* A, float* B, float* C, int N) {
    __shared__ float tA[16][16], tB[16][16];
    int row = blockIdx.y*16+threadIdx.y, col = blockIdx.x*16+threadIdx.x;
    float sum = 0;
    for (int t = 0; t < N/16; t++) {
        tA[threadIdx.y][threadIdx.x] = A[row*N + t*16+threadIdx.x];
        tB[threadIdx.y][threadIdx.x] = B[(t*16+threadIdx.y)*N + col];
        __syncthreads();             // 타일 로딩 완료 대기
        for (int k=0;k<16;k++) sum += tA[threadIdx.y][k]*tB[k][threadIdx.x];
        __syncthreads();             // 덮어쓰기 전 대기
    }
    C[row*N+col] = sum;
}

각 원소를 매번 global에서 읽는 대신 16×16 타일을 shared에 한 번 올려 재사용 → 메모리 접근이 수십 배 줄어 성능이 크게 오릅니다.

6.3 Bank Conflict — shared memory의 함정

shared memory는 32개 뱅크로 나뉩니다. 한 warp의 여러 스레드가 같은 뱅크의 다른 주소에 동시 접근하면 직렬화됩니다(bank conflict).

  • 충돌 없음 — 스레드들이 서로 다른 뱅크에 접근 (또는 같은 주소 = 브로드캐스트)
  • 회피 — 흔히 패딩으로: __shared__ float tile[16][16+1]; (열을 +1 패딩해 뱅크 정렬을 어긋나게)

6.4 Occupancy & 분기 최소화

  • Occupancy — ④에서 본대로 레지스터·shared 사용을 조절해 SM에 충분한 warp 확보(latency hiding). 단 100%가 항상 최적은 아님.
  • Warp divergence 최소화 — warp 안 분기를 줄이기. 데이터를 정렬하거나 분기 없는(branchless) 코드로.
  • 전송 숨기기 — 스트림 overlap + pinned memory로 복사·연산 겹치기.

6.5 프로파일링 — 추측하지 말고 측정하라

최적화의 첫걸음은 병목을 찾는 것입니다. NVIDIA 도구:

도구용도
Nsight Systems (nsys)전체 타임라인 — CPU/GPU/스트림/전송 overlap 파악
Nsight Compute (ncu)커널 단위 심층 — occupancy, 메모리 처리량, 병합률, bank conflict
 
nsys profile ./app          # 타임라인 수집
ncu --set full ./app        # 커널 메트릭 심층
⚠️ 직접 짜기 전에

행렬 곱·FFT·reduction 등은 라이브러리가 거의 항상 더 빠릅니다 — cuBLAS, cuFFT, CUB/Thrust, CUTLASS를 먼저 고려하세요. 직접 최적화는 그걸로 안 될 때.

6.6 최적화 체크리스트 (우선순위 순)

  1. 프로파일링으로 병목 확인 (memory-bound? compute-bound?)
  2. 메모리 병합 — 가장 효과 큼
  3. shared memory 재사용 (타일링), bank conflict 회피
  4. occupancy 확보 (latency hiding 충분할 만큼)
  5. 분기 최소화, 전송 overlap
  6. 반복 워크로드는 CUDA Graphs로 launch 오버헤드 제거
  7. 라이브러리로 대체 가능한지 항상 확인
