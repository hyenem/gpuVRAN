Part 1 · GPU 아키텍처 기초

"GPU는 왜 빠른가?"의 직관을 잡는 것이 목표입니다. 이 그림이 잡히면 CUDA 코드가 왜 그렇게 생겼는지, vRAN 가속이 왜 GPU에 맞는지 자연스럽게 이해됩니다.

1.1 CPU vs GPU — 설계 철학의 차이

CPU와 GPU는 둘 다 연산을 하지만, 완전히 다른 목표로 설계됐습니다.

  • CPU = 지연시간(latency) 최적화 — 하나의 작업을 최대한 빨리 끝내도록. 큰 캐시, 분기 예측, 비순차 실행(out-of-order) 등 복잡한 제어 로직에 트랜지스터를 투자합니다. 코어 수는 적지만(수~수십 개) 각각이 매우 똑똑합니다.
  • GPU = 처리량(throughput) 최적화 — 똑같은 연산을 수천~수만 개 데이터에 동시에 적용. 제어 로직은 최소화하고 ALU(연산기)를 대량으로 채웁니다. 코어 하나는 단순하지만 수천 개가 병렬로 돕니다.
CPUGPU

최적 작업순차적·분기 많은 로직대규모 데이터 병렬

🧠 핵심 직관

"같은 계산을 수많은 데이터에 반복"하는 작업이라면 GPU가 압도적으로 유리합니다. 영상의 모든 픽셀, 행렬의 모든 원소, 그리고 — 무선 신호의 모든 서브캐리어 같은 것들이죠. 이게 vRAN과 GPU가 만나는 지점입니다.

1.2 SIMT · Warp · SM — GPU 실행 모델

GPU 하드웨어를 이해하는 핵심 3가지 개념입니다.

SIMT (Single Instruction, Multiple Threads)

GPU는 하나의 명령어를 여러 스레드가 동시에 실행합니다. CPU의 SIMD(하나의 명령어로 여러 데이터)와 비슷하지만, GPU는 이걸 "스레드" 단위로 추상화해서 프로그래머가 일반적인 스칼라 코드처럼 짜면 하드웨어가 알아서 병렬로 돌립니다. 이것이 SIMT입니다.

Warp (워프)

GPU 스레드는 개별적으로 도는 게 아니라 32개가 한 묶음(warp)으로 묶여 같은 명령어를 함께 실행합니다(NVIDIA 기준). warp가 하드웨어 스케줄링의 기본 단위입니다.

⚠️ Warp Divergence (분기 발산)

한 warp 안의 32개 스레드가 if/else로 갈라지면, GPU는 양쪽 경로를 순차적으로 실행하며 해당 안 되는 스레드는 쉽니다. 즉 분기가 많으면 성능이 급락합니다. "warp 안에서는 모두 같은 길을 가게 하라"가 최적화의 기본 원칙입니다.

SM (Streaming Multiprocessor)

GPU는 여러 개의 SM으로 구성됩니다. SM 하나가 CUDA 코어 수십~수백 개, 워프 스케줄러, 레지스터 파일, 공유 메모리(shared memory), L1 캐시를 담고 있는 "작은 프로세서"입니다. 우리가 실행하는 thread block은 하나의 SM에 배정되어 돌아갑니다. 

# GPU 계층 구조
GPU
 └─ 여러 개의 SM (Streaming Multiprocessor)
      └─ CUDA 코어들 + 워프 스케줄러 + 공유 메모리 + 레지스터
           └─ Warp (32 스레드 묶음)
                └─ Thread (개별 스레드)
💡 Occupancy (점유율)

SM은 동시에 여러 warp를 올려놓고, 한 warp가 메모리를 기다리며 멈추면 즉시 다른 warp로 전환해 ALU를 놀리지 않습니다(latency hiding). 그래서 SM에 충분히 많은 warp를 올리는 것 — 높은 occupancy — 가 GPU 성능의 열쇠입니다.

1.3 메모리 계층 — GPU 성능의 진짜 병목

많은 GPU 프로그램이 연산이 아니라 메모리 접근에서 막힙니다(memory-bound). 메모리 종류와 속도를 아는 것이 최적화의 절반입니다.

핵심 ① — Coalesced Access (메모리 병합 접근)

한 warp의 32개 스레드가 연속된 메모리 주소를 읽으면, GPU는 이를 하나의 큰 트랜잭션으로 묶어 처리합니다(coalescing). 반대로 제각각 흩어진 주소를 읽으면 트랜잭션이 쪼개져 대역폭이 낭비됩니다. "스레드 i가 배열 i를 읽게 하라"가 황금률입니다.

핵심 ② — Shared Memory 활용

global memory는 느리므로, 여러 번 쓰일 데이터는 한 번 읽어 shared memory에 올려두고 재사용합니다. 행렬 곱(타일링), FFT, 컨볼루션 등 거의 모든 고성능 커널의 핵심 기법입니다.

⚠️ Bank Conflict

shared memory는 32개 뱅크로 나뉘어 있어, 한 warp의 여러 스레드가 같은 뱅크에 동시 접근하면 직렬화됩니다. 접근 패턴 설계 시 주의할 부분이며, 보통 패딩으로 회피합니다.

🔧 vRAN과의 연결

NVIDIA의 vRAN 플랫폼은 Grace CPU + GPU를 결합한 형태(예: GH200, 그리고 vRAN 전용 NVIDIA Grace Hopper 기반 시스템)로 발전하고 있습니다. CPU가 스케줄링·제어 평면을, GPU가 무거운 신호처리(L1)를 맡는 구조죠. 자세한 건 Part 3에서 다룹니다.

Tensor Core

일반 CUDA 코어 외에, 행렬 곱셈-누적(MMA)을 한 번에 처리하는 Tensor Core가 있습니다. 원래 딥러닝용이지만, 빔포밍·채널 추정 같은 vRAN의 행렬 연산에도 활용 여지가 큽니다.

✅ Part 1 정리

① GPU는 처리량 최적화 — 같은 연산을 수천 데이터에 병렬. ② 실행은 warp(32스레드) 단위, SM에서 스케줄링. ③ 성능은 메모리 계층(coalescing, shared memory)이 좌우. 이 셋만 기억하면 Part 2의 CUDA 코드가 술술 읽힙니다.
