② CUDA 프로그래밍

①의 하드웨어 개념을 실제 코드로 다룹니다. CUDA는 C++ 확장이며, 핵심은 "어떤 데이터를 어떤 스레드가 처리할지" 매핑하는 일입니다.

2.1 프로그래밍 모델 — Grid / Block / Thread

병렬 작업은 3단 계층으로 조직됩니다. 이 구조가 ①의 하드웨어(SM, warp)에 그대로 매핑됩니다.

  • Thread — 가장 작은 실행 단위. 보통 데이터 원소 하나 처리.
  • Block — 스레드 묶음. 같은 블록끼리 shared memory 공유 + 동기화 가능. 한 SM에서 실행.
  • Grid — 블록의 묶음. 커널 하나 = grid 전체.
// 각 스레드가 자신의 전역 인덱스를 계산하는 공식
int idx = blockIdx.x * blockDim.x + threadIdx.x;
//        ↑ 몇 번째 블록   ↑ 블록 크기   ↑ 블록 내 위치
🧩 핵심 사고법

CUDA 프로그래밍 = "내가 처리할 배열 인덱스를, 내 스레드 좌표(blockIdx, threadIdx)로부터 어떻게 계산할까?"를 정하는 일. 나머지는 평범한 C++입니다.

2.2 첫 커널 — 벡터 덧셈

// CPU: 루프로 하나씩
void vecAdd_cpu(float* A, float* B, float* C, int n) {
    for (int i = 0; i < n; i++) C[i] = A[i] + B[i];
}

// GPU: 각 스레드가 원소 하나 담당 (루프가 사라짐)
__global__ void vecAdd(float* A, float* B, float* C, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) C[i] = A[i] + B[i];   // 범위 보호
}

__global__은 "GPU에서 실행, CPU에서 호출되는 함수(=커널)" 표시입니다. 루프 대신 수천 스레드가 각자 한 원소씩 동시에 처리합니다.

호스트(CPU) 쪽 실행

int n = 1<<20;  size_t bytes = n*sizeof(float);
float *dA,*dB,*dC;
cudaMalloc(&dA, bytes); cudaMalloc(&dB, bytes); cudaMalloc(&dC, bytes);
cudaMemcpy(dA, hA, bytes, cudaMemcpyHostToDevice);   // CPU→GPU 복사
cudaMemcpy(dB, hB, bytes, cudaMemcpyHostToDevice);

int threads = 256;                            // 블록당 스레드 (보통 128~512)
int blocks  = (n + threads - 1) / threads; // 올림 나눗셈
vecAdd<<<blocks, threads>>>(dA, dB, dC, n);   // ← 커널 실행!

cudaMemcpy(hC, dC, bytes, cudaMemcpyDeviceToHost); // 결과 회수
cudaFree(dA); cudaFree(dB); cudaFree(dC);

<<<blocks, threads>>>가 CUDA 특유의 실행 구성(launch configuration) 문법입니다. 이 실행이 실제로 어떻게 도는지는 ③ 실행 모델에서 깊게 봅니다.

2.3 메모리 관리

전통 방식 — 명시적 복사

위처럼 cudaMalloc + cudaMemcpy로 host↔device를 명시적으로 복사합니다.

Unified Memory

float *A;
cudaMallocManaged(&A, bytes);  // CPU/GPU가 같은 포인터, 시스템이 자동 이동
💡 Pinned Memory

cudaMallocHost로 할당한 pinned(page-locked) memory는 전송이 빠르고 비동기 복사가 가능합니다. 스트림 overlap(③)의 전제 조건입니다.

에러 체크는 습관처럼

#define CUDA_CHECK(call) do { cudaError_t e=(call); \
  if(e!=cudaSuccess){ fprintf(stderr,"%s:%d %s\n",__FILE__,__LINE__,cudaGetErrorString(e)); exit(1);} \
} while(0)
CUDA_CHECK(cudaMalloc(&dA, bytes));

2.4 동기화 — 블록 안에서의 협력

같은 블록의 스레드들은 협력할 수 있습니다 (다른 블록끼리는 커널 안에서 직접 동기화 불가).

  • __syncthreads() — 블록 내 모든 스레드가 이 지점에 도달할 때까지 대기 (배리어). shared memory를 함께 쓸 때 필수.
  • 아토믹 연산 — atomicAdd 등으로 여러 스레드가 같은 주소를 안전하게 갱신 (경쟁 조건 방지). 단 경합 시 직렬화되니 남용 금지.
__shared__ float tile[256];
tile[threadIdx.x] = A[idx];     // 각자 shared에 적재
__syncthreads();              // 모두 적재 끝날 때까지 대기
// 이제 tile을 안전하게 함께 사용
⚠️ 경쟁 조건(race)

여러 스레드가 동기화 없이 같은 메모리를 읽고 쓰면 결과가 비결정적입니다. shared memory 공유 패턴엔 __syncthreads()를, 누적엔 아토믹 또는 reduction 패턴을 쓰세요.

✅ ② 정리

커널은 __global__, 인덱스는 blockIdx*blockDim+threadIdx. cudaMalloc/Memcpy로 메모리 관리, 블록 내 협력은 __syncthreads()·아토믹. 다음은 "이 커널이 실제로 어떻게 실행되는가"입니다.
