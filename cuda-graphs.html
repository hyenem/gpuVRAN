CUDA Graphs 심화

실시간 결정론 기법에서 핵심으로 꼽았던 CUDA Graphs를 끝까지 파봅니다. 한 줄 요약 — 반복되는 GPU 작업 시퀀스를 "그래프"로 한 번 캡처해, 매번 통째로 launch해서 launch 오버헤드와 지터를 없애는 기술입니다.

1. 왜 그래프인가 — launch 오버헤드와 지터

커널을 하나 launch할 때마다 CPU 쪽 오버헤드(드라이버 처리, ~µs)가 듭니다. vRAN처럼 작은 커널 수십 개를 매 슬롯 반복하면, 이 launch 비용이 쌓여 — 연산보다 launch가 병목이 되고, 커널 사이 간격(gap)과 지터가 마감을 위협합니다. 

// 매 슬롯 이렇게 N번 launch → N번의 CPU 오버헤드 + 지터
fft<<<...>>>();  chanEst<<<...>>>();  mimo<<<...>>>();  ldpc<<<...>>>();  ...

// 그래프: 한 번 캡처해두고 매 슬롯 한 방에 launch
cudaGraphLaunch(graphExec, stream);   // 1번의 launch로 전체 시퀀스 실행
💡 얻는 것 3가지
  • launch 비용 분할상환 — N번 → 1번
  • CPU 해방·지터↓ — CPU는 한 번 던지고, GPU가 그래프를 자율 실행
  • 드라이버 최적화 — 전체 워크플로를 미리 알기에 커널 간 간격·스케줄을 더 잘 짬 → 결정론적 타이밍

2. 3단계 동작 — 정의 → 인스턴스화 → 실행

그래프 작업은 세 단계로 분리됩니다. 비싼 셋업은 한 번만, 실행은 싸게 반복이 핵심입니다.

단계무엇비용
① 정의 (definition)노드(커널·memcpy 등)와 의존성(DAG) 구성 → cudaGraph_t1회
② 인스턴스화 (instantiation)실행 가능 객체로 컴파일 (검증·최적화) → cudaGraphExec_t1회 (비쌈)
③ 실행 (execution)cudaGraphLaunch로 반복 재생(replay)매번 (쌈)

그래프는 노드(작업) + 엣지(의존성)의 DAG입니다. 노드 종류: 커널, memcpy, memset, host 함수, child graph, event record/wait, conditional 등.

3. 만드는 법 — Stream Capture vs Explicit API

① Stream Capture (가장 쉬움)

기존 스트림 코드를 Begin/EndCapture로 감싸면, 그 안에서 던진 작업들이 자동으로 그래프에 기록됩니다. 의존성은 스트림·이벤트 사용에서 추론됩니다.

cudaStreamBeginCapture(stream, cudaStreamCaptureModeGlobal);
fft<<<...,stream>>>();          // 이 블록의 모든 작업이
chanEst<<<...,stream>>>();      // 실행되지 않고 "기록"됨
mimo<<<...,stream>>>();
ldpc<<<...,stream>>>();
cudaStreamEndCapture(stream, &graph);   // → cudaGraph_t 완성

② Explicit API (정밀 제어)

노드를 하나씩 추가하고 의존성을 명시합니다. 구조를 세밀하게 다룰 때.

cudaGraphCreate(&graph, 0);
cudaGraphAddKernelNode(&nFft, graph, NULL, 0, &fftParams);
cudaGraphAddKernelNode(&nCh,  graph, &nFft, 1, &chParams);   // nFft에 의존
// ... 노드·엣지를 명시적으로 구성

4. 업데이트 — 매 슬롯 재파라미터화

vRAN의 묘미가 여기 있습니다. 슬롯마다 데이터 포인터·크기만 바뀌고 구조는 같다면, 그래프를 다시 만들 필요 없이 파라미터만 갱신하면 됩니다.

방식설명
노드 단위 업데이트cudaGraphExecKernelNodeSetParams 등으로 특정 노드 파라미터 변경
전체 그래프 업데이트cudaGraphExecUpdate — 위상이 동일한 새 그래프로 파라미터 일괄 교체
 
// 빌드·인스턴스화는 1회, 매 슬롯엔 포인터만 갱신 + launch
for (slot = 0; ; slot++) {
    cudaGraphExecKernelNodeSetParams(graphExec, fftNode, &newParams);  // 슬롯 데이터 포인터
    cudaGraphLaunch(graphExec, stream);
}
📌 중요한 성질

업데이트는 다음 launch부터 적용되고, 이미 실행 중인 launch엔 영향 없습니다. 그래서 갱신·재실행을 스트림에 줄줄이 큐잉할 수 있습니다. 단 위상(topology)은 동일해야 함 — 노드를 추가/삭제하려면 재빌드가 필요합니다.

5. 고급 — Conditional Node & Device Graph Launch

Conditional Nodes (CUDA 12.3+)

그래프 구조가 고정이라 동적 제어 흐름이 약점이었는데, conditional node(IF/WHILE 컨테이너)가 이를 풉니다. 노드 안의 body graph가 조건 변수 값에 따라 실행됩니다.

  • 조건 핸들을 미리 만들고, 커널에서 cudaGraphSetConditional로 조건 값을 설정
  • IF: 조건이 0이 아니면 body를 1회 실행 / WHILE: 조건이 참인 동안 반복
  • vRAN 예 — LDPC 반복 횟수가 가변(수렴하면 조기 종료)이거나, 조건부 처리 분기에 활용

Device Graph Launch (CUDA 12+)

GPU 커널이 직접 다른 그래프를 launch할 수 있습니다 — CPU를 안 거치고요. GPU 코드가 "다음에 어떤 사전 빌드 그래프를 돌릴지" 동적으로 정할 수 있어, CPU↔GPU 왕복을 없애는 계층적 실행이 가능합니다. GPU 주도(GPUNetIO) 철학과 맞물립니다.

6. vRAN 적용 · 함정

vRAN L1의 슬롯당 파이프라인(FFT→채널추정→MIMO→LDPC)은 매 슬롯 똑같이 반복되는 고정 시퀀스 → 그래프의 교과서적 사례입니다. 

// vRAN 사용 패턴
빌드 + 인스턴스화 (init 1회)
 └─ 매 슬롯: 노드 파라미터 갱신(슬롯 데이터) → cudaGraphLaunch
            → launch 지터 제거, µs 마감 안정, CPU 부하↓

persistent kernel·스트림과 함께 쓰여 결정론을 끌어올립니다.

⚠️ 함정
  • 구조 고정 — 위상을 바꾸려면 재빌드. 동적 분기는 conditional node로 일부만 해결.
  • 빌드·인스턴스화 비용 — 한 번만 하라. 매 슬롯 재빌드하면 오히려 손해.
  • 업데이트 제약 — 위상 동일해야 파라미터 갱신 가능.
  • 캡처 중 동기 호출 금지 — capture 모드에선 일부 동기 API가 막힘(주의).
✅ 한 줄 정리

CUDA Graphs = 정의→인스턴스화(1회)→실행(반복). 반복되는 커널 시퀀스를 한 번 캡처해 매 슬롯 파라미터만 갱신하고 통째로 launch → launch 오버헤드·지터 제거. vRAN 슬롯 파이프라인에 딱 맞고, conditional node(가변 LDPC)·device launch(CPU 우회)로 확장됩니다.
