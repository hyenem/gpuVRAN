실전 사례: inline vs lookaside 두 진영

이론을 넘어 실제 상용·트라이얼 사례를 봅니다. 핵심 반전부터 — "GPU vRAN"과 "lookaside"는 현실에서 거의 다른 진영입니다. GPU를 택하면 자연히 inline(NVIDIA Aerial)으로 가고, lookaside를 택하면 보통 GPU가 아닌 Intel/FPGA로 갑니다.

🔑 한 줄 핵심

GPU를 lookaside로 쓰면 함수마다 PCIe 왕복이 생겨 GPU의 장점이 죽습니다. 그래서 NVIDIA는 아예 "vRAN엔 programmable inline 가속이 필수"라고 주장하며 inline으로 갔고, 상용 GPU vRAN은 사실상 모두 inline입니다.

1. Inline — "GPU에서 다 하는 방식" 사례

모두 NVIDIA Aerial(cuPHY) 기반입니다. NIC/DPU가 안테나 데이터를 GPUDirect로 GPU에 직접 꽂고, GPU 안에서 FFT→채널추정→MIMO→LDPC를 전부 처리합니다.

① SoftBank "AITRAS" — 가장 진전된 상용형

  • 구성: NVIDIA GH200(Grace Hopper) + BlueField-3 DPU + Spectrum-X 네트워킹으로 풀 5G vRAN 스택.
  • 성과: 실제 필드 트라이얼에서 16-layer massive MIMO를 완전 소프트웨어 정의로 구현 — 업계 최초 수준의 이정표.
  • 의미: 우리가 본 "NIC/DPU→GPUDirect→GPU 인라인 처리, CPU는 경로 밖" 구조의 실제 구현체.

② T-Mobile · Indosat Ooredoo Hutchison

NVIDIA Aerial RAN Computer(ARC) 기반 AI-RAN 엔게이지먼트 진행. ARC는 Grace Hopper/GB200 기반 vRAN 서버이고, 셀 사이트(기지국 현장)용 소형 버전인 ARC-Compact도 있습니다.

③ Nokia anyRAN on NVIDIA

Nokia의 RAN 소프트웨어(anyRAN)를 NVIDIA AI Aerial 플랫폼에서 검증 → 랩 검증에서 상용 배포로 이동 중(MWC 2026 시연). 기존 RAN 벤더가 GPU 플랫폼을 채택하는 흐름의 신호.

④ 솔루션 파트너 생태계

Mavenir, Capgemini, Fujitsu, Kyocera 등이 Aerial 위에 L1/스택을 통합. 즉 cuPHY를 직접 안 짜도 그 위에서 제품을 올리는 생태계가 형성돼 있습니다.

🤖 왜 이렇게 활발한가 — AI-RAN

이 사례들이 공통적으로 "AI-RAN"으로 묶이는 이유: RAN 부하가 낮을 때 같은 GPU로 AI 추론을 돌려 장비를 양용하기 때문입니다. 딜레마 페이지에서 본 "종속의 대가로 얻는 것" — GPU 범용성의 실제 사업 논리입니다.

2. Lookaside — 실제로는 대부분 비(非)-GPU

상용 vRAN의 lookaside는 GPU가 아니라 이쪽입니다. L1은 CPU(Xeon)에서 돌고 LDPC 같은 무거운 함수만 DPDK bbdev API로 가속 카드에 외주합니다.

사례종류내용
Intel ACC100eASICFEC 전용 가속기. LDPC enc/dec를 bbdev로 PCIe 카드에 외주
Intel vRAN BoostCPU 내장Sapphire Rapids-EE에 FEC 가속을 SoC에 통합 → 별도 카드 제거
AccelerCommFPGA IPbbdev 호환 lookaside FEC 가속 IP
Ericsson + Verizon진영Cloud RAN에서 lookaside를 지지 — NVIDIA의 inline 주장과 대립
⚠️ GPU를 lookaside로 쓰는 경우는?

주로 학술 벤치마크입니다. 최근 DecodeX(arXiv, 2025) 논문처럼 LDPC 디코딩을 CPU vs GPU vs ASIC로 비교하는 연구가 그 예고, 상용 제품으로 GPU 전용 lookaside FEC 카드는 사실상 없습니다. GPU lookaside는 PCIe 왕복 오버헤드 때문에 상용성이 떨어지기 때문입니다.

3. 왜 NVIDIA 말고 다른 GPU는 없는가

자연스러운 질문 — "AMD나 Intel GPU로는 vRAN을 안 하나?" 답은 상용에선 거의 없다이고, 그 이유가 곧 종속 딜레마의 가장 적나라한 모습입니다. 경쟁사들은 GPU로 NVIDIA에 맞서지 않습니다 — 아예 다른 칩으로 갑니다.

회사vRAN 가속 베팅GPU인가?
NVIDIAAerial/cuPHY (inline GPU)✅ GPU
IntelFlexRAN — Xeon SIMD(AVX) + vRAN Boost(내장 FEC)❌ CPU+ASIC
AMDEPYC CPU(Zen5 벡터로 LDPC), Xilinx FPGA(T1 카드)❌ CPU+FPGA
QualcommX100 5G 가속 카드 (전용 DSP/inline)❌ 전용 가속기
MarvellOCTEON Fusion (DPU)❌ DPU

즉 "GPU vRAN = NVIDIA"가 현재 거의 동의어입니다. AMD Instinct·Intel Arc 같은 GPU가 기술적으로 못 하는 게 아니라, 아무도 그 위에 vRAN L1 스택을 만들지 않았습니다. 이유 셋:

  1. cuPHY가 CUDA 전용 — 핵심 L1 라이브러리(cuPHY/cuBB)는 CUDA로만 돈다. AMD ROCm·Intel oneAPI에는 대응하는 성숙한 L1 스택이 없어 처음부터 다시 짜야 한다.
  2. 진짜 해자(moat)는 수직 통합 스택 — GPU 단품이 아니라 GPU + BlueField DPU + GPUDirect + Spectrum-X + Aerial SDK가 한 묶음. 경쟁사는 이 "RAN-on-GPU 풀스택"을 안 만들었다.
  3. 경쟁사는 자기가 강한 곳으로 — Intel은 CPU(AVX)+내장 FEC, AMD는 EPYC+FPGA, Qualcomm은 전용 DSP. 자사 GPU(Instinct/Arc)는 vRAN이 아니라 AI/HPC·미디어용으로 포지셔닝한다.
⚠️ 그래서 진짜 구도

질문은 "어떤 GPU를 쓸까?"가 아니라 "GPU(=NVIDIA)로 갈까, 아니면 다른 종류의 칩(CPU/FPGA/ASIC/DSP)으로 갈까?"입니다. GPU 안에서의 벤더 선택지는 현재 사실상 없습니다 — 종속을 피하려면 GPU 자체를 포기해야 합니다.

🔮 이 독점을 흔들 장기 요인

① CXL — 개방 인터커넥트로 GPUDirect 같은 독점 훅 의존도↓. ② O-RAN AAL — 가속 API 표준화로 다른 가속기 진입 문턱↓. ③ AMD ROCm 생태계 성장. 단, 셋 다 아직 미래형이라 당분간은 NVIDIA 우위가 이어집니다.

✅ 결론

"GPU vRAN"과 "lookaside"는 현실에선 거의 다른 진영입니다. GPU를 택하면 자연스럽게 inline(NVIDIA Aerial)으로, lookaside를 택하면 보통 GPU가 아닌 Intel/FPGA로 갑니다. 이것이 "성능 vs 개방성" 딜레마가 시장에서 실제로 갈라지는 모습입니다. 개발 방향을 정할 때 — "GPU로 간다 = inline으로 간다"를 사실상 기본 전제로 깔고 시작하면 됩니다.
