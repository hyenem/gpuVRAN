① GPU 아키텍처

"GPU는 왜 빠른가, 안에서 무슨 일이 벌어지는가"의 직관을 잡는 게 목표입니다. 이 그림이 잡히면 CUDA 코드가 왜 그렇게 생겼는지, 스케줄링이 왜 그렇게 도는지 자연스럽게 이해됩니다.

1.1 CPU vs GPU — 설계 철학

  • CPU = 지연시간(latency) 최적화 — 하나의 작업을 최대한 빨리. 큰 캐시·분기예측·비순차실행 등 복잡한 제어 로직에 트랜지스터를 투자. 코어는 적지만(수~수십) 각자 매우 똑똑.
  • GPU = 처리량(throughput) 최적화 — 같은 연산을 수천~수만 데이터에 동시에. 제어 로직은 최소화하고 ALU를 대량으로 채움. 코어 하나는 단순하지만 수천 개가 병렬.
CPUGPU
코어 수수~수십수천 (CUDA 코어)
코어 1개매우 빠름·복잡단순
캐시크고 계층적상대적으로 작음
지연 숨기기큰 캐시로 줄임많은 스레드로 가림
최적 작업순차·분기 많은 로직대규모 데이터 병렬
🧠 핵심 직관

"같은 계산을 수많은 데이터에 반복"이면 GPU가 압도적입니다. 영상의 모든 픽셀, 행렬의 모든 원소, 신경망의 모든 가중치 같은 것들. 이 패턴을 어떻게 코드로 표현하느냐가 CUDA의 전부입니다.

1.2 SM 내부 구조 — GPU의 기본 프로세서

GPU 하나는 수십~수백 개의 SM(Streaming Multiprocessor)으로 이루어집니다. SM 하나가 "작은 독립 프로세서"이고, 우리가 실행하는 thread block이 SM에 배정되어 돌아갑니다. 

GPU
 ├─ SM 0 ─┐  각 SM이 블록들을 받아 독립 실행
 ├─ SM 1  │  (GigaThread 엔진이 블록을 SM에 분배)
 └─ SM N ─┘

SM 안에는 무엇이 (예: Ampere/Hopper, 아키텍처마다 다름)

구성요소역할
CUDA 코어 (~128 FP32/SM)일반 산술 (덧셈·곱셈)
Tensor 코어 (~4/SM)행렬 곱-누적(MMA), 딥러닝
Warp 스케줄러 (보통 4개/SM)매 사이클 실행할 warp 선택
레지스터 파일 (65,536 × 32bit ≈ 256KB/SM)스레드 지역 변수
Shared memory / L1 (~최대 228KB/SM)블록 내 협력·캐싱
LD/ST, SFU메모리 접근, 특수함수(sin/sqrt)

핵심 — SM은 레지스터·shared memory·warp 슬롯을 "고정 예산"으로 가진 단위입니다. 이 예산이 occupancy의 전부예요.

1.3 SIMT · Warp — GPU 실행의 단위

SIMT (Single Instruction, Multiple Threads)

GPU는 하나의 명령어를 여러 스레드가 동시에 실행합니다. 프로그래머는 평범한 스칼라 코드처럼 짜면, 하드웨어가 알아서 병렬로 돌립니다. CPU의 SIMD를 "스레드" 단위로 추상화한 것이 SIMT입니다.

Warp (워프)

스레드는 개별로 도는 게 아니라 32개가 한 묶음(warp)으로 같은 명령어를 함께 실행합니다(NVIDIA). warp가 하드웨어 스케줄링의 기본 단위입니다.

⚠️ Warp Divergence (분기 발산)

한 warp의 32개 스레드가 if/else로 갈라지면 GPU는 양쪽 경로를 순차 실행하며 해당 안 되는 스레드는 쉽니다. 분기가 많으면 성능이 급락 → "warp 안에서는 모두 같은 길을 가게 하라"가 원칙.

# 계층 구조
Grid (커널 전체)
 └─ Block (thread block, 한 SM에 배정)
      └─ Warp (32 스레드)
           └─ Thread

1.4 메모리 계층 — GPU 성능의 진짜 병목

많은 GPU 프로그램이 연산이 아니라 메모리 접근에서 막힙니다(memory-bound). 종류와 속도·공유 범위를 아는 것이 최적화의 절반입니다.

메모리공유 범위속도
레지스터스레드 전용가장 빠름
Shared Memory블록 내 (SM 내부)매우 빠름
L1 캐시SM빠름
L2 캐시모든 SM빠름
Global Memory (VRAM)모든 스레드느림 (수백 사이클)
Constant / Texture모든 스레드 (캐시·읽기전용)읽기 최적화

핵심 둘은 메모리 병합(coalescing)과 shared memory 재사용 — ⑥ 최적화에서 자세히 다룹니다. 지금은 "global은 느리고, 가까운 메모리에 올려 재사용하는 게 핵심"만 기억하세요.

1.5 Occupancy — SM에 warp를 얼마나 채우나

SM이 동시에 품는 warp 수는 자원 한계 중 가장 빡빡한 것에 막힙니다. 이 비율(거주 warp ÷ 최대)이 occupancy입니다.

한계예 (Ampere)
최대 warp/SM64 warp (= 2048 스레드)
최대 블록/SM~32 블록
레지스터/SM65,536개 → 스레드가 많이 쓰면 warp↓
shared memory/SM~164KB → 블록이 많이 쓰면 블록↓

예 — 커널이 스레드당 레지스터 64개 쓰면: 2048 × 64 = 131,072 > 65,536 → 절반(32 warp)만 거주 → occupancy 50%.

💡 왜 occupancy가 중요한가

SM에 warp가 충분히 많아야, 한 warp가 메모리를 기다리며 멈출 때 다른 warp로 0-오버헤드 전환해 ALU를 놀리지 않습니다(latency hiding). 이게 "많은 스레드로 지연을 가린다"는 GPU의 핵심이고, ④ 스케줄링에서 더 깊게 봅니다.

✅ ① 정리

GPU는 처리량 기계 — 같은 연산을 수천 데이터에 병렬. 실행은 warp(32스레드) 단위로 SM에서. 성능은 메모리 계층과 occupancy가 좌우. 이 넷이 ②~⑥의 토대입니다.
