Part 3 · GPU vRAN 가속

이제 본론입니다. 무선 기지국의 신호처리를 GPU로 가속한다는 게 구체적으로 무엇인지, 어떤 연산 블록이 있고 왜 GPU에 맞는지, 그리고 실무 플랫폼(NVIDIA Aerial)이 어떻게 생겼는지 정리합니다.

3.1 vRAN / O-RAN 기초

RAN이란?

RAN(Radio Access Network)은 단말(폰)과 코어망을 잇는 무선 기지국 네트워크입니다. 5G 기지국(gNB)은 기능적으로 셋으로 나뉩니다:

  • RU (Radio Unit) — 안테나·RF. 실제 전파 송수신.
  • DU (Distributed Unit) — L1(물리계층/PHY)과 L2 일부. 가장 연산이 무거운 곳. ← GPU 가속 핵심
  • CU (Centralized Unit) — 상위 계층(L2/L3), 제어.

vRAN과 O-RAN

  • vRAN (virtualized RAN) — 전용 하드웨어(ASIC/FPGA)로 하던 일을 범용 서버 + 소프트웨어로 구현. 유연성·확장성·비용 절감이 목표.
  • O-RAN — 인터페이스를 표준·개방화해 서로 다른 벤더 장비를 섞어 쓸 수 있게 하는 진영/표준. RU와 DU 사이의 Open Fronthaul (7.2x split)이 대표적입니다.
🔑 핵심 split: 7.2x

O-RAN은 RU와 DU 사이를 "7.2x"라는 지점에서 나눕니다. RU는 FFT/iFFT·빔포밍 일부 같은 저수준만, 나머지 무거운 L1 처리는 DU(=서버+GPU)가 맡습니다. 즉 우리가 GPU로 가속할 대상은 주로 DU의 L1(High-PHY)입니다.

3.2 왜 GPU인가?

5G NR의 물리계층은 본질적으로 대규모 병렬 신호처리입니다. 예를 들어:

  • 한 슬롯에 수천 개의 서브캐리어(subcarrier)를 동시에 처리
  • 여러 레이어·안테나(MIMO)에 걸친 행렬 연산
  • 수많은 코드블록에 대한 독립적 FEC 디코딩

이 "같은 연산을 수많은 데이터에 독립적으로" 패턴이 바로 Part 1에서 본 GPU의 특기입니다. 게다가 5G는 사용자·셀이 늘수록 부하가 커지는데, GPU는 코어를 추가 투입해 유연하게 스케일할 수 있습니다(동일 서버에서 AI 워크로드와 공존도 가능 — "AI-RAN").

방식장점단점
ASIC최고 효율·저전력고정 기능, 개발비·기간 큼
FPGA재구성 가능, 저지연개발 난이도, 용량 한계
GPU소프트웨어 유연성, 대규모 병렬, AI 공존전력·지연 관리가 과제

Inline vs Lookaside 가속

  • Lookaside — CPU가 주 흐름을 처리하다 특정 무거운 함수(예: LDPC)만 가속기에 "외주". 데이터 왕복 오버헤드 존재.
  • Inline — L1 파이프라인 전체를 가속기(GPU) 안에서 처리. NVIDIA Aerial의 접근으로, 데이터 이동을 줄여 저지연에 유리.

3.3 L1/PHY 가속 블록

DU의 L1에서 GPU가 처리하는 주요 신호처리 블록입니다. 대부분 Part 2의 CUDA 커널 또는 NVIDIA 라이브러리로 구현됩니다.

① FEC — LDPC / Polar 코딩

무선은 노이즈가 많아 오류 정정 부호(FEC)가 필수입니다. 5G 데이터 채널은 LDPC, 제어 채널은 Polar 코드를 씁니다. 특히 LDPC 디코딩은 반복적(iterative) 연산이라 매우 무겁고, 수많은 코드블록을 병렬 디코딩하기 좋아 GPU의 대표적 가속 대상입니다.

② FFT / iFFT — OFDM 변복조

5G는 OFDM 방식이라 송신 시 iFFT, 수신 시 FFT가 핵심입니다. 수천 점 FFT를 슬롯마다 대량으로 — cuFFT 또는 전용 커널로 가속합니다.

③ 채널 추정 · 등화 (Channel Estimation / Equalization)

파일럿 신호(DMRS)로 무선 채널 상태를 추정하고, 왜곡을 보정합니다. 안테나×레이어 차원의 행렬 연산이 많아 Tensor Core·cuBLAS 활용 여지가 큽니다.

④ MIMO 검출 · 빔포밍 (Beamforming)

여러 안테나를 이용해 신호를 특정 방향으로 집중(빔포밍)하거나, 여러 레이어를 분리(MIMO 검출)합니다. 본질이 대규모 행렬 곱이라 GPU에 매우 적합합니다.

⑤ 변조 / 복조, 스크램블링, 레이트 매칭

QAM 매핑/디매핑, scrambling, rate matching 등 비교적 가벼운 블록들도 전체 인라인 파이프라인 안에서 GPU로 처리됩니다. 

// 상향링크(UL) 수신 파이프라인 개략 (PUSCH)

3.4 NVIDIA Aerial · cuPHY

NVIDIA Aerial은 GPU에서 5G vRAN의 L1을 구현하는 소프트웨어 플랫폼(SDK)입니다. 핵심 구성:

  • cuPHY — 5G L1/PHY를 CUDA로 구현한 라이브러리. 위에서 본 LDPC, FFT, 채널추정, 빔포밍 등을 GPU 커널로 제공. 인라인 가속 구조.
  • cuMAC — MAC 계층 스케줄링 가속.
  • Aerial CUDA-Accelerated RAN — O-RAN 인터페이스(Fronthaul 등)와 통합된 전체 DU L1 스택.
  • Aerial Omniverse Digital Twin / Sionna — 채널 시뮬레이션·연구용 도구(Sionna는 링크레벨 시뮬레이션 라이브러리).
🏗️ 하드웨어 플랫폼

Aerial은 Part 1에서 언급한 Grace Hopper(GH200) 같은 CPU+GPU 통합 플랫폼과 ConnectX/BlueField(고속 네트워킹, PTP 시각 동기)와 결합해 동작합니다. Fronthaul의 정밀한 시간 동기가 vRAN에서 매우 중요합니다.

📚 시작 지점

실제 개발에 들어가기 전, NVIDIA Aerial 개발자 페이지와 Sionna로 링크레벨 시뮬레이션부터 손에 익히는 것을 추천합니다. cuPHY 내부 커널을 읽어보면 Part 1·2 지식이 실제로 어떻게 쓰이는지 보입니다.

3.5 실시간 제약 — vRAN의 진짜 난이도

vRAN이 어려운 이유는 연산량보다 "제 시간에 끝내야 한다"는 실시간성에 있습니다.

  • 슬롯 타이밍 — 5G NR은 시간이 슬롯으로 쪼개져 있고(예: 30kHz SCS에서 슬롯 = 500μs), 매 슬롯의 처리를 그 안에 끝내야 합니다.
  • HARQ 타이밍 — 수신 후 정해진 시간 내에 ACK/NACK을 보내야 해, L1 처리에 주어진 시간은 수백 μs 수준으로 빡빡합니다.
  • 지터(jitter) 관리 — 평균이 빠른 것으로 부족하고, 최악 지연(tail latency)이 예산을 넘으면 안 됩니다. 결정론적(deterministic) 동작이 핵심.
⚠️ 그래서 필요한 기법들

Part 2에서 배운 스트림 overlap, CUDA Graphs(launch 오버헤드 제거), persistent kernel(커널을 계속 띄워두고 일감을 받기), GPUDirect(NIC→GPU 직접 DMA로 CPU 우회), pinned memory가 모두 이 지연 예산을 맞추기 위해 동원됩니다. CPU 코어 격리(isolcpus), 실시간 커널, NUMA 배치 같은 시스템 튜닝도 함께 갑니다. → 각 기법을 디테일하게 정리한 페이지

✅ Part 3 정리 & 다음 단계

vRAN = 서버+SW로 구현한 기지국, GPU가 가속하는 곳은 DU의 L1/PHY. 핵심 블록은 LDPC·FFT·채널추정·빔포밍이고, 이들은 모두 GPU의 병렬성에 잘 맞습니다. 실무 플랫폼은 NVIDIA Aerial(cuPHY). 가장 어려운 부분은 연산이 아니라 μs 단위 실시간 마감이며, 여기에 Part 2의 모든 최적화가 총동원됩니다.
