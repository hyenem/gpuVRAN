실시간 결정론 기법

Part 3의 실시간 제약에서 "그래서 필요한 기법들"로 나열했던 것들을 하나씩 디테일하게 풉니다. 각 기법을 무엇 / 왜 실시간에 필요 / 어떻게 / 트레이드오프로 정리했습니다.

1. 왜 "결정론(determinism)"인가

vRAN이 어려운 건 연산량이 아니라 "매 슬롯을 제 시간에 끝내야 한다"는 점입니다. 그리고 핵심은 — 평균이 빠른 것으로는 부족하고, 최악 지연(tail latency)이 마감을 넘으면 안 된다는 것.

  • 슬롯 마감 — 예: 30kHz SCS에서 슬롯 = 500µs. 매 슬롯 처리를 그 안에 끝내야 함.
  • HARQ 타이밍 — 수신 후 정해진 시간에 ACK/NACK을 보내야 해 L1 예산이 수백 µs로 빡빡.
  • 지터(jitter) — 한 번이라도 마감을 넘기면 슬롯 전체가 무효. 그래서 "평균 100µs"가 아니라 "99.999%가 200µs 이내" 같은 보장이 필요.

아래 기법들은 전부 이 꼬리(tail)를 짧고 예측 가능하게 만들기 위한 것입니다. 크게 GPU 기법 · 시스템 기법 · 데이터 경로 기법 세 갈래입니다.

2. GPU 쪽 기법

① 다중 스트림 Overlap

  • 무엇: 작업을 여러 CUDA 스트림에 나눠 전송과 연산을 동시에 진행
  • 왜: 데이터 복사 시간을 연산 뒤에 숨김(hide). "수신→처리→송신"이 겹쳐 돌아 슬롯 지연↓
  • 어떻게: cudaMemcpyAsync + 커널을 서로 다른 스트림에. pinned memory 필수
  • 트레이드오프: 스트림 관리 복잡도, 자원 경합 가능

② CUDA Graphs

  • 무엇: 매 슬롯 반복되는 커널·복사 시퀀스를 그래프로 한 번 캡처해 통째로 launch
  • 왜: 커널 하나하나 launch할 때 드는 CPU 오버헤드(수 µs) + 지터를 제거. 마감이 빡빡한 L1에 결정적
  • 어떻게: cudaStreamBeginCapture → 그래프 인스턴스화 → 매 슬롯 cudaGraphLaunch 한 방
  • 트레이드오프: 그래프 구조가 고정이라 동적 분기가 많으면 부적합

③ Persistent Kernel

  • 무엇: 커널을 GPU에 계속 띄워둔 채 루프 돌며 일감(슬롯)을 받음 (매번 launch 안 함)
  • 왜: launch 지연을 완전히 0으로. 가장 지연에 민감한 부분에 사용
  • 어떻게: 커널이 메모리 플래그/큐를 폴링하다 새 슬롯이 오면 처리
  • 트레이드오프: SM을 점유한 채 busy-wait(전력·자원 소모), 설계 난이도 높음

④ GPUDirect RDMA

  • 무엇: NIC→GPU 메모리 직접 DMA, CPU·시스템RAM 우회
  • 왜: 복사 단계와 CPU 개입(지터)을 데이터 경로에서 제거
  • 어떻게: nvidia-peermem + RDMA NIC(ConnectX/BlueField), GPU 메모리를 peer로 등록
  • 트레이드오프: NIC·GPU가 같은 PCIe/NUMA에 있어야 효과 (→ nvidia-smi topo)

⑤ Pinned (page-locked) Memory

  • 무엇: OS가 못 옮기는 고정 호스트 메모리
  • 왜: DMA가 바로 가능 → 전송이 빠르고 비동기·결정론적. 스트림 overlap의 전제 조건
  • 어떻게: cudaMallocHost
  • 트레이드오프: 물리 메모리를 묶어둠(과하면 시스템 압박)

3. 시스템 / OS 쪽 기법 (지터·tail latency 잡기)

⑥ 코어 격리 (CPU isolation)

  • 무엇: 특정 CPU 코어를 vRAN 스레드 전용으로 떼어내고 OS 스케줄러·다른 태스크를 차단
  • 왜: 선점(preemption)·문맥교환이 없어야 결정론적. tail latency의 주범 제거
  • 어떻게: isolcpus, nohz_full(tickless), IRQ affinity로 인터럽트도 격리
  • 트레이드오프: 그 코어는 다른 용도로 못 씀

⑦ 실시간 커널 (PREEMPT_RT)

  • 무엇: 리눅스 커널을 선점 가능하게 만들어 스케줄링 지연에 상한을 둠
  • 왜: 평균이 아니라 최악 지연을 보장해야 슬롯 마감을 못 어김
  • 어떻게: PREEMPT_RT 패치 커널, RT 우선순위(SCHED_FIFO)
  • 트레이드오프: 평균 처리량 약간↓, 튜닝 필요

⑧ NUMA 배치

  • 무엇: NIC·GPU·메모리·스레드를 같은 NUMA 노드(소켓)에 배치
  • 왜: 소켓 간 이동(UPI/QPI 홉)은 지연·지터를 키움. 같은 노드면 최단 경로
  • 어떻게: numactl로 메모리/CPU 바인딩, nvidia-smi topo -m으로 토폴로지 확인 후 배치
  • 트레이드오프: 자원 배치 제약

⑨ 자주 함께 가는 것들

  • Hugepages — 큰 페이지로 TLB 미스↓ (DPDK 기본 요구)
  • Busy-poll (DPDK poll-mode) — 인터럽트 제거, 폴링으로 초저지연 패킷 수신
  • C-state / 주파수 governor 고정 — CPU가 절전에서 깨어나는 지연 제거(performance governor)
  • 핫패스 사전 할당 — 슬롯 처리 루프에서 malloc/페이지 폴트 금지, 버퍼 미리 확보

4. 무엇이 무엇을 잡나

지연/지터의 원인잡는 기법

✅ 한 줄로 꿰면

GPU 기법(graphs·persistent·overlap)은 연산 지연·지터를, 시스템 기법(코어격리·RT·NUMA)은 OS 지터를, 데이터 경로 기법(GPUDirect·pinned)은 이동 지연을 잡습니다. 셋이 다 모여야 "매 슬롯 µs 마감"을 결정론적으로 지킬 수 있습니다 — 하나만 빠져도 꼬리가 튑니다.
